# 🏗️ Design Mode Template

## Шаблон для проектирования и архитектуры

```text
[ARCH] #технология
Контекст: текущее состояние системы, ограничения, требования.
Задача: спроектировать архитектуру/схему/интерфейс.
Подходы: какие варианты рассматриваются.
Критерии выбора: производительность, безопасность, масштабируемость.
Ожидаемый результат: схема, диаграмма, структура файлов.
```

## Примеры

### [ARCH] #fastapi
Контекст: нужно добавить метрики API к существующему Express серверу.
Задача: спроектировать структуру endpoints для аналитики пользователей.
Подходы: отдельный сервис vs интеграция в существующий.
Критерии: минимальные изменения, высокая производительность, легкое тестирование.
Ожидаемый результат: схема API, структура папок, примеры запросов.

### [ARCH] #database
Контекст: Mindora растет, нужно оптимизировать запросы к PostgreSQL.
Задача: спроектировать индексы и партиционирование для таблицы token_usage.
Подходы: B-tree индексы vs частичные индексы, партиционирование по дате.
Критерии: быстрые запросы за последние 30 дней, экономия места.
Ожидаемый результат: SQL скрипты, диаграмма индексов, план миграции.

### [ARCH] #security
Контекст: админ-панель должна быть максимально защищена.
Задача: спроектировать систему аутентификации без паролей.
Подходы: Cloudflare Access vs Auth0 vs самописное решение.
Критерии: простота настройки, надежность, возможность аудита.
Ожидаемый результат: схема аутентификации, настройки CF, тесты безопасности.
